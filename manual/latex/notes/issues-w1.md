# User-facing problems mentioned by w1 (Quick start, Ch. 1-3, App. C)

Format: Symptom | Why | What to do | Chapter label

- **Every start prints "MODELLER not found ... To install: conda install -c salilab modeller" although MODELLER is installed** | In 1.23.0 the message is printed whenever MODELLER cannot be imported, which also happens when only the license key is missing (the usual case after Option A/B without a key) | Do not reinstall MODELLER; add the key (`mkdir -p ~/.proprep && echo 'YOUR_KEY' > ~/.proprep/modeller_key`). Without a key everything except loop/residue/atom repair, standard mutations and homology models works | ch:installation (sec:installation-modeller-msg), app:software
- **tLEaP/sander/force-field files come from a different Amber installation (paths such as `.../envs/etanalyze_env/bin/teLeap` in tLEaP warnings)** | ProPrep keeps an AMBERHOME that is already set in the shell; no warning is given | Before starting, `echo $AMBERHOME`; if it names another folder, `unset AMBERHOME` (Option A) or `conda activate ProPrep` + `source $CONDA_PREFIX/amber.sh` (Option B) | ch:installation (sec:installation-amberhome)
- **Option B installer says "Homology modeling will not be available" when the key is skipped** | Wording: it means every MODELLER-based tool, including structure repair | Add the key later as in sec:installation-modeller | ch:installation
- **MD run stops with "Error starting simulation: [Errno 2] No such file or directory: 'pmemd'"** | Default engine at the hardware step is pmemd, which the free install does not contain; "recommended" assignment picks pmemd.cuda even with 0 GPUs | At Hardware choose 3 (all same engine) -> 1 sander (or 2 sander.MPI); Manage queue cannot change it later, go back through Setup -> Hardware | ch:quickstart, ch:runningmd, app:software
- **5a: answering Enter (n) to "Do you want to continue without bond definitions?" throws the whole tLEaP input away** | Default answer is n | Type y for an ordinary protein | ch:quickstart, ch:topology
- **`proprep-library` fails with "bad interpreter: .../python3.13"** (Option B conda env) | Launcher script points at Python 3.13; env has 3.12 | Run `python -m proprep.utils.user_library_snapshots <same options>` inside the env | ch:installation, ch:forcefields
- **Browser shows "This site can't be reached" at 127.0.0.1:8000** | proprep-web not running, or it moved to another port | Start `proprep-web` again; use the address it prints, e.g. "(port 8420 was busy; using 8421)" | ch:installation, ch:starting
- **Installer: "No such file or directory" / "Permission denied" / "ERROR: File or directory already exists" / "No space left on device"** | Wrong/incomplete file name; missing `bash`; already installed; < 8 GB free | Tab-complete the name; start the line with `bash`; add `-u` to update; free 8 GB (from INSTALL.md, not reproduced) | ch:installation
- **Option B: "ERROR: conda is not installed or not in your PATH."** | No Miniforge/conda | Install Miniforge, open a new Terminal, rerun | ch:installation
- **Option B: "ERROR: expected ProPrep 1.23.0 but conda resolved: ..."** (source only) | conda chose another version | Read conflicts; on a Mac try `SYSTEM_VERSION_COMPAT=0 bash install_proprep.sh` | ch:installation
- **AlphaFold load without internet says the protein has no AlphaFold prediction** | Misleading message; real cause is no connection | Check the internet connection | app:software, ch:structure
- **Standard mutations (4b) silently not applied without MODELLER; non-standard ones only when a terminal cap is also added** | No-MODELLER branch of 4c | Get a MODELLER key, or add at least one cap for non-standard mutations | app:software, ch:cleaning
- **ORCA route in 5c: "Step 2 failed: orca_mm not found", traceback, no files** | orca_mm (part of ORCA) is needed even to write the inputs | Install ORCA and give its folder, or use the Gaussian route | app:software, ch:qmmm
- **2c stops with "Gaussian output not found" plus a traceback** | Gaussian must be run by the user; no AM1-BCC route in 2c | Run g16 on the written .gjf (elsewhere if needed) and resume; or make AM1-BCC parameters with antechamber outside ProPrep and import them | app:software, ch:forcefields
- **ProPrep accepts TIP3P water with ff19SB without a warning** (its own list says to use OPC) | No compatibility check | Read the list descriptions; pick OPC for ff19SB | ch:whatis, ch:topology

Not a user problem but worth knowing (docs): the exit-screen citation title ("ProPrep: An Interactive and Instructional Interface for Proper Protein Preparation with AMBER") differs from the article title in CITATION.cff ("ProPrep: (Metallo)protein MD Preparation That Keeps Users Informed and in Control"). The manual quotes the exit screen and points to CITATION.cff.
