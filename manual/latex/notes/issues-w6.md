## Chapter 17 — Membrane Builder (4g)

- **"tLEaP could not add the hydrogens ... Build anyway with packmol-memgen's own protonation? [y/n] (n)", and if you answer y, 6–7 minutes later "The protein in bilayer.pdb is not the one packmol-memgen was given ... The build is not recorded."** | The structure still contains ions, crystal waters or other residues tLEaP cannot type (1BL8 has 3 K+ and 1 water in the filter). packmol-memgen's own protonation then trims and renumbers residues, so ProPrep's safety check rejects the packed file. | Answer `n`. Remove every non-protein component with 4a PDB Filter first, then build again. A bilayer.pdb left by a refused build is not registered in the workspace. | ch:membrane
- **Lipid, box and orientation settings are back at their defaults when you re-open 4g** | Selecting a different protein, filtering the structure, or coming back after a build silently clears them. Nothing says so. | Read the "Current Configuration" block or press `r` (review) before every build. | ch:membrane
- **A setting made earlier in a different sub-menu is lost after typing `undo`** | Observed once: a PACKMOL time limit of 0.25 h was back at `none` after a rewind inside the force-field walkthrough (could also have been the config reset above). | Check the review (`r`) after any `undo`. | ch:membrane
- **"Error executing PDB Filter.filter_pdb_structure: invalid literal for int() with base 10: '1-97'" and the whole filter run is abandoned** | 4a's residue selector (option `s`) does not accept ranges; a traceback is logged and the selections made so far are lost. | Type comma-separated numbers or `all`. | ch:membrane (also ch:cleaning)
- **5a says "✓ Topology files generated (1 prmtop files)" before you have generated anything** | It counts the internal pretleap_hydrogen.prmtop written by the hydrogen-adding step, which also appears as a second row in the tLEaP file table. | Run option 4 anyway and check that bilayer.prmtop exists. | ch:membrane
- **A solvate-only (no lipids) build still writes bilayer.pdb and the review still lists "Lipid: lipid21 / leaprc needed: leaprc.lipid21"** | Wording/limitation of the shared code path. | Ignore it; the system really has no lipids. | ch:membrane
- **820–132 tLEaP warnings scroll past after a membrane build** | Lipid atom/residue renaming plus close contacts from packing. | Normal as long as the summary says "Errors = 0"; the minimization relaxes the contacts. | ch:membrane
- **"Sterols and/or PI are used, and the concentration is too high or the system too small..."** | 25 % cholesterol in a 40 Å patch is dense for packmol-memgen's padding rules. | Use a larger patch. | ch:membrane
- **Screens show packmol-memgen and teLeap running from a different conda environment than ProPrep's** | ProPrep takes external programs from `$AMBERHOME/bin` first. | Check which AmberTools `AMBERHOME` points at when a build behaves oddly. | ch:membrane, ch:troubleshooting

## Chapter 18 — Molecular Docking (5d)

- **"Template matching failed for: ['A:99', 'B:99']" / "Creation of data structure for receptor failed", with a Python traceback** | The PDB has no OXT atoms, but ProPrep proposed "C-terminus: charged COO-" because SEQRES says no residues are missing. Meeko's message does not mention OXT. | Option 4 → type the residue (A:99) → answer `b` (chain break); repeat per chain. Or add OXT with the Structure Fixer. ProPrep's own default is the one that fails on this very common kind of file. | ch:docking
- **Docking "succeeds" in under a second with weak scores (~ -4 kcal/mol) and no RMSD column** | The search box was defined with `l` around a SMILES-built ligand, which sits at the coordinate origin, not in the protein. ProPrep warns beforehand but does not check that the box overlaps the receptor. | Define the box with `r` (around named residues) or `c` (typed centre/edges). | ch:docking
- **Scores look fine but the pocket is blocked** | The crystal ligand was left "keep" in option 3 while docking something else into the same site. | Leave it out in option 3, or pick it as the ligand (option 2 `s`), which removes it from the receptor automatically. | ch:docking
- **The top-scoring pose is not the right one** | With ad4 on 1HSG, pose 1 scored -12.88 at 4.05 Å from the crystal pose, while pose 5 (-11.24) was 1.78 Å. vina and vinardo put the right pose first (0.46 Å and 0.41 Å). | Look at the first few poses, use the RMSD column when a crystal pose exists, and start with vina. | ch:docking
- **"The ligand could not be built: Unsupported ligand file type '.smi'; use .sdf, .mol or .mol2." but the dashboard still shows a ligand** | A .smi library works for the loader and for a campaign, but not as a single ligand; the failed attempt leaves its name on line 2. | Use a campaign, or an .sdf/.mol/.mol2 file. Check the dashboard before running. | ch:docking
- **The search box and the kept-HETATM list are empty after changing the ligand** | Both belonged to the previous ligand and are cleared. | Set the box again after every ligand change. | ch:docking
- **"⚠ Needs a loaded structure" when choosing 5d** | No structure loaded; the menu just re-prints. | Load one with 1a first. | ch:docking
- **ad4 runs take much longer than vina** | ad4 needs AutoGrid maps built per receptor and box (59 s against 17 s here). | Use vina for first tries. | ch:docking

## Chapter 21 — Sessions

- **ProPrep replays everything and quits before you can type** | "Continue from end" on a session that recorded a normal exit replays the exit too; files are re-created on the way through. | Open the Session Editor and delete the last two answers (`d 18-end`), or use Continue only on interrupted sessions. | ch:sessions
- **Pressing Enter in the session picker starts a fresh session** | The default answer is `0`, which means cancel. | Type the number of the file. | ch:sessions
- **No "Previous session files found!" question although a session exists** | The file lives in the project subfolder; ProPrep only looks in the folder it was started in (and in `--session-dir`). | `cd` into the project folder before starting. | ch:sessions
- **`undo` → `[c]hange` keeps the old answer: "[REPLAY: 'r' now means a different option; using 'd' → Discard entire component]"** | The stored option label is not updated for menu questions, and replay matches on the label. | Use `[r]` (re-answer live) or the Session Editor, which does update it. | ch:sessions
- **A project folder called `undo` appears** | `undo` typed at the project-name question, before recording starts, is taken literally. | Delete the folder and start again. | ch:sessions
- **"Invalid choice: undo. Please try again."** | Recording is off (`--no-session`, startup choice 3, or a pure replay). | Restart without `--no-session`. | ch:sessions
- **"Error: [Errno 2] No such file or directory: 'sessions/...json'" right after the project question, followed by "Session saved to: ..."** | `--session-dir` with a relative path or a folder that does not exist; the path is resolved after ProPrep moves into the project folder, and the "saved" line is printed although nothing was written. | Always give an absolute path to a folder that already exists. | ch:sessions
- **A typing mistake appears in the undo list as an answer** | Invalid menu entries are recorded like any other answer. | Harmless; rewind past it if it bothers you. | ch:sessions
- **The replay stops to ask the menu-mode question** | That question happens before recording starts, so it is not in the file. | Add `--full-menu` (or `--workflow`) to replay commands. | ch:sessions
- **"The recorded session was started with --pdbfile my_protein.pdb, but that file is not here..."** | The structure file the recording began from is missing; replay continues with no structure, so every tool reports "Needs a loaded structure". | Copy the file in, or replay with `--pdbfile <path>`. | ch:sessions
- **No "Session saved to:" line on a normal exit, only "[Session recording stopped]"** | Cosmetic. | The file is there. | ch:sessions

## Chapter 22 — Templates and batch

- **Every run fails with "Setup error: [Errno 2] No such file or directory: 'batch_out/run_01'" and the batch ends in a Python traceback instead of a summary** | `--output-dir` does not create the folder. | `mkdir` the output folder before running. | ch:batch
- **A template has no blanks although you expected the PDB ID to be found** | Auto-detection of variables is switched off in 1.23.0; nothing is pre-marked. | Mark answers yourself with `v <#>` in the Template Creator. | ch:batch
- **"Replay diverged: no recorded answer for prompt ... the recording expects a prompt here: ..." for one protein** | That protein is asked different questions than the recorded one (1CRN has no crystal waters, so the water question never comes). | Choose proteins with the same make-up (chains, waters, ligands), or record a template that fits them. Use `--batch-continue` to finish the rest. | ch:batch
- **A run "succeeds" but the output is wrong** | Batch replay does not validate choice values: a water option of `x` is accepted silently and the waters are kept. `--validate-template` does not check them either. | Check list values by eye. | ch:batch
- **"! Input column 'P69905' matches no template variable" / "Variable 'input_protein' ...: no run supplies a value" for a plain list of UniProt IDs** | A first line starting with a letter is taken for a CSV header. PDB codes start with a digit and are unaffected. | Put the line `input_protein` at the top of the file. | ch:batch
- **A full Python traceback is printed over the progress bar when a protein fails** | Batch failures leak their log lines onto the display. | The same text is in that run's `error.log`; read it there. | ch:batch
- **A terminal-recorded template fails at the chain-selection question when forced with `--web`** | In browser mode the PDB Filter's viewer question is skipped, so the recording gets out of step. | Let ProPrep choose the mode (it is taken from the recording), or match the mode to the recording. | ch:batch
- **Typing `quit` right after `e <#>` stores "quit" as the answer** | The editor expects the new value next. | Finish the edit, then quit. | ch:batch
- **"No variables marked. A template needs at least one variable."** | `save` pressed with no `v` marks. | Mark at least one answer, or save it as an edited session instead. | ch:batch
